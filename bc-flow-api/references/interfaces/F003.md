# F003 Get product prices

The external sales channel calls the Flow platform to get product prices.

Operation: read; distribution documentation: listed.

## Backend behavior

Returns prices and available plan units under the channel policy. The reviewed backend reads skuId for rate limiting but does not filter the actual price query by it; select the target SKU locally when the response contains all products. Interpret amounts using the channel currency and field contract; do not apply eSIM Access's USD /10000 conversion.

Call chain: `SaleController.dispatchRequest` → `SaleApiService.queryGoodsPrice`.
Source: `flow@93d717b36c/manage-api/src/main/java/com/op/flow/manage/api/service/SaleApiService.java:2088`; see [Protocol and environments](../protocol.md) for test-branch differences.

## Using quotes

- Use `call F003 ... --sku-id ID --summary` to select the exact SKU. Keep all quotes for it and choose the requested units/days; do not assume the first quote or use another product's price. Local filtering does not change the full API response or bypass rate limits. Reuse an existing complete local result when available.
- Responses generally omit currency. Use a reliable existing channel settlement agreement; otherwise show the raw amount with "Channel pricing units; currency not returned by the API." Do not guess CNY/USD or convert. Routine queries need not stop or repeatedly ask about currency; clarify it when the user requests conversion, a currency-specific budget or a cross-channel comparison.
- `copies` means plan units. The backend quote uses `days = copies × days per unit`; these match only for one-day units. Card-only products may return `days=0`. Keep the corresponding quote values together; do not interchange days and units.
- A long quote such as 1095 days is not by itself evidence of bad data. Preserve it without adjusting/deleting its price or selecting it by default; unrelated quotes need not interrupt the user. F040 validates each supplied `days` and `planSkuCopies` as 1–730. A quote does not guarantee an order can use that same number; do not substitute arbitrary units to bypass validation. Explain the constraint and investigate only when the requested long duration cannot be mapped to a valid order.
