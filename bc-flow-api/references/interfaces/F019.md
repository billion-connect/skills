# F019 Update an after-sales request

The sales channel can obtain the list of commodities it can sell, with external sales channel application system as the calling party , And the sales channel can change the after sale apply

Operation: write; distribution documentation: not listed (this alone does not prove the backend cannot support it).

## Backend behavior

Updates an after-sales request by afterSaleId. Conditional validation includes return tracking details and agreed refund amount. The reviewed test branch requires API after-sales allowlisting.

The refund method remains constrained by the original reason. When editing a comment for a reason `29` request, retain `refundType=0` and the original cancellation/receipt/return conditions; do not switch to an agreed amount. This endpoint has no field for changing the reason. Verify the updated state using F020.

First confirm with F020 that the request has not been reviewed. An approved request (auditStatus=2) cannot be changed even before the refund arrives; observed rejection: `1112 / This application cannot be modified`.

Call chain: `SaleController.dispatchRequest` → `SaleApiService.modifyAfterSale`.
Source: `flow@93d717b36c/manage-api/src/main/java/com/op/flow/manage/api/service/SaleApiService.java:4693`; see [Protocol and environments](../protocol.md) for test-branch differences.
