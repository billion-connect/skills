# F002 List products

The external sales channel calls the Flow platform to list products.

Operation: read; distribution documentation: listed.

## Backend behavior

Returns only listed products visible under the channel's policy. Primary and distribution channels use separate product queries. Full queries are rate-limited; prefer skuId/countryCode filters.

Call chain: `SaleController.dispatchRequest` → `SaleApiService.queryGoodsHandle`.
Source: `flow@93d717b36c/manage-api/src/main/java/com/op/flow/manage/api/service/SaleApiService.java:2013`; see [Protocol and environments](../protocol.md) for test-branch differences.

## Selecting products

Use structured `country[].mcc/name` for destination coverage; names and descriptions are display text. Do not interrupt users for each placeholder label in test products or remove products solely because of such labels. If a name contradicts structured coverage, do not promise additional destinations from the name.

An eSIM name, `applyToDevice`, or a particular `type` alone does not establish F040 eligibility. Backend candidate types include 230, 3105, 3106, 110, 111 and 250 (eSIM Air); channel policies, resources and product rules still apply. Do not restrict candidates to 3105/3106 or treat type 212/213 as eSIM plans just because the name contains eSIM. The response has no `f040Eligible` field; do not invent one.

Select candidates using the user's destination, plan and current channel catalog/quotes. Ask for missing details together without making users interpret internal product types. Never place real orders to probe eligibility in bulk. For large lists, use `--country-code`, `--product-type`, `--sku-id` and `--summary`; see [Local product and price display](../credentials.md#local-product-and-price-display).
